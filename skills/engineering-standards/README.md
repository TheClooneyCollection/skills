# engineering-standards

Build and review app code with standards for simple objects, single responsibility, strong boundaries, dependency injection and testable state. Each rule starts with a principle and keeps Swift as one example.

**Why:** TBD

**Use it:** when designing app architecture, wiring dependencies, writing view models or view states, mapping network data and errors, or reviewing code against these standards.

**Needs:** Nothing to install. Test shape, doubles, factories and fixtures follow the `behavior-tests` skill.

## Files

- [SKILL.md](SKILL.md): five core rules, reference pointers and the completion check.
- [references/structure.md](references/structure.md): rules 6–12 for structure and dependencies.
- [references/screen-state.md](references/screen-state.md): rules 13–18 for screen state and presentation.
- [references/tests.md](references/tests.md): rules 19–22 for test boundaries, fixtures and offline coverage.
